# T93 — Category picker shows colors and filters by typing
- **Goal:** The Category field in the item edit form shows every category with its assigned color and narrows by typed substring, like the main-screen product pickup.
- **Inputs:** `item-edit-form.tsx` (native select, no colors), `useCategories` (API `sortOrder` = creation order), main-screen pickup pattern (`category-add-item-input.tsx`: popover, Escape/blur close), HeadlessUI (already a dep; `Combobox` unused so far), RHF `Controller` (unused so far).
- **Outputs:** New `category-select.tsx` (HeadlessUI `Combobox` via RHF `Controller` on `categoryId`; all categories in API order by default, client-side substring filter while typing, swatch + title per row, swatch on the picked value); `item-edit-form.tsx` uses it when categories are known, keeps the read-only paragraph when null; validation (`categoryId` min 1) unchanged.
- **Test cases:** 1. Setup: Dairy (blue) + Bakery (orange); Action: open the picker; Expected: both rows show title plus the correctly colored swatch in API order. 2. Setup: same; Action: type "bak"; Expected: only Bakery remains. 3. Setup: same; Action: pick Bakery, Save; Expected: PATCH carries Bakery's id and the field shows Bakery with its swatch. 4. Setup: same; Action: keyboard only (open, arrows, Enter); Expected: selection changes without a mouse. 5. Setup: categories unknown (deep link); Action: open the form; Expected: read-only category title, no picker. 6. Setup: any item; Action: edit, save, edit again; Expected: T92 Saved/re-arm behavior unchanged.
- **Definition of Done:** Test cases 1–6 pinned by specs (new combobox spec + existing details/swipe/saved specs green); full gate green.
- **Dependencies:** T92.
