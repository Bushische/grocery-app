# T65 — Privacy-ON adaptation: reply-to-message + deterministic multi-item split
- **Goal:** Chat commands work fully with group privacy ON: `/buy …` with several products adds each; `/buy` as a reply consumes the quoted list message.
- **Inputs:** T62 (webhook + secret + gating), T63 (dialog + list resolution), Bot API privacy semantics (with privacy ON the bot still gets `/commands` — including a `/command` reply to another user's plain-text message, WITH `reply_to_message` — plus mentions and replies to its own messages; plain group text never arrives; the bot must be RE-ADDED to groups after flipping the switch).
- **Outputs:** `telegram/protocol.ts` (+ `reply_to_message.text` shape), webhook: `/command`-as-reply uses the quoted text as the product source (own command text wins when non-empty, e.g. `/buy in Home` replying to a list); `botDialog.ts` deterministic splitter (lines → commas/semicolons → `and/и`, each fragment through `smartAddItem`, cap 20, one summary reply `Added "a", "b" (+N more)`); `/setcommands` list (`buy`, `list`, `bought`, `unbuy`) for autocomplete; docs (`/setprivacy` ON + re-add note, Step 8b update).
- **Definition of Done:** inject tests — `/buy milk, bread` adds two; reply-`/buy` to a 3-line list adds three; `/buy in Second` reply routes by suffix; plain group text needs no test (never delivered); unlinked reply-author still gets the link prompt; full gate green. No LLM yet.
- **Dependencies:** T62, T63.
