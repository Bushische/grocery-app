# T95 — Cache item photos locally for 7 days

- **Goal:** Opening an item with a photo must not hit the network on every click — a locally cached copy (fresh for at least 7 days) is shown instantly, including in the Telegram WebView where the service worker may not run.
- **Inputs:** `image-upload.tsx` + `item-edit-sheet.tsx` (both render `/static/<filename>` directly today), `pwa-config.ts` (SW CacheFirst for `/static`, 365 d — complements but does not cover WebViews), `test/image-stub.ts` (`stubObjectUrls` pattern for jsdom).
- **Outputs:** New `features/items/lib/image-cache.ts` (IndexedDB store `grocery-image-cache`, in-memory object-URL map, TTL 7 days, paint-first: network URL renders immediately while the cache warms in the background) + `features/items/hooks/use-cached-image.ts` (`useCachedImageSrc(filename)` → cached object URL when fresh, else `/static/…`); both photo views use the hook so the preview, thumbnail, and lightbox all serve from the local copy.
- **Test cases:** 1. Setup: warm cache entry < 7 days old; Action: render the photo; Expected: object URL shown with zero `fetch` calls. 2. Setup: entry > 7 days old or absent; Action: render; Expected: `/static/…` shown immediately, background fetch re-stores a fresh blob. 3. Setup: network fetch fails; Action: render; Expected: `/static/…` still shown, no crash. 4. Setup: re-uploaded photo (new content-addressed filename); Action: render; Expected: new URL fetched, old entry never served. 5. Setup: existing `image-upload`/`item-details` suites; Action: run; Expected: green, first-paint assertions unchanged.
- **Definition of Done:** Test cases 1–5 pinned by specs (new cache + hook specs; existing suites green); repeat views within 7 days issue no `/static` network requests; full gate green.
- **Dependencies:** T93.
