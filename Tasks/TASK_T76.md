# T76 — Swipe-to-action on rows: left Edit dialog, right slide-to-delete (touch only)
- **Goal:** Swipe left to edit, swipe right (and further) to delete — working on Android; desktop right-click keeps opening details.
- **Inputs:** `item-row.tsx` (long-press + right-click → details), details-page two-step delete, `useDeleteItem`, `ItemEditForm`, TouchSensor 150 ms/5 px + `movedSinceDown` tap-suppress pattern.
- **Outputs:** Hand-rolled swipe on the row body (no new deps, pure helper unit-tested like `reorderedIdsAfterDrag`): `touch-action: pan-y` so Android Chrome delivers horizontal moves (vertical scroll untouched); two thresholds per direction — reveal past ~1/3, commit on release past ~2/3 (else snap back), trailing tap never toggles; swipe left reveals Edit → release-to-commit or tap opens an edit bottom-sheet reusing `ItemEditForm` (title/qty/category); swipe right reveals a red DELETE underlayer on the left → sliding further arms it (`Release to delete`) and releasing there deletes (the far slide is the confirmation; 403 reverts via the existing error path); long-press removed (replaced, avoids gesture fights); revealed actions are real focusable buttons (≥40 px targets).
- **Definition of Done:** Real-Android pass (Chrome) + jsdom/pure-helper pins: left-commit opens the edit sheet and saves; right-commit arms then deletes on second confirm; short swipes snap back; vertical scroll never reveals; tap after swipe never toggles; mouse suite: right-click still opens details, no swipe path; full gate green.
- **Dependencies:** T75.
